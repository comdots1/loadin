동적 세그먼트 워크 스틸링 (Dynamic Work-Stealing)

고정 분할 방식의 한계를 원천 극복합니다. 먼저 작업을 끝낸 고루틴(Goroutine)이 현재 진행 중인 가장 큰 세그먼트(남은 용량 ≥ 1MB)를 실시간 감지하여 중간 지점을 원자적으로 분할(Atomic Bisect)하고 즉시 새로운 HTTP Range 연결을 생성합니다. 마지막 1바이트까지 모든 스레드가 100% 가동됩니다.

// Atomic Work-Stealing Bisect Algorithm
mid := remaining.Start + (remaining.End - remaining.Start)/2
newSegment := &SegmentState{Start: mid, End: remaining.End, Status: "streaming"}

병합 지연 0초 (Positional I/O)

임시 분할 파일(.part1, .part2)을 내려받아 합치느라 디스크가 멈추는 현상이 없습니다. 디스크 공간을 선할당(Truncate)하고 Win32 오프셋 기반 os.File.WriteAt으로 락-프리 직접 기록합니다.

윈도우 시스템 트레이 연동

Shell_NotifyIconW 네이티브 API 연동으로 마우스 호버 시 실시간 전송 속도 및 진행 건수 툴팁을 표시합니다. 창을 닫아도 백그라운드에서 가볍게 상주하며 즉시 복원됩니다.

온디맨드 네이티브 추가 창 & loadin://

화면을 가리는 위젯 없이, 브라우저에서 다운로드 링크를 클릭했을 때만 560×412 크기의 C# 네이티브 창(AetherHover)이 즉시 나타납니다. loadin:// 시스템 프로토콜 완벽 지원.

Frequently Asked Questions

자주 묻는 질문

Loadin에 대해 궁금한 점들을 명쾌하게 정리했습니다.

Q. '병합 지연 0초'는 기술적으로 어떻게 작동하나요? ▾
기존 다운로더는 각 스레드마다 별도의 임시 파일(.part)을 다운로드한 후, 99%에서 하나의 파일로 디스크를 다시 읽고 복사하여 합칩니다. 이 과정에서 수 기가바이트의 디스크 읽기/쓰기 멈춤이 발생합니다.

Loadin은 작업 시작 시 대상 파일 크기만큼 디스크를 Truncate로 선할당하고, 각 고루틴이 Win32 위치 직접 I/O(os.File.WriteAt)로 해당 바이트 위치에 병렬 락-프리 직접 기록합니다. 따라서 마지막 바이트가 도착하는 순간 이미 원본 파일이 완성되어 있어 병합 시간이 0.00초입니다.
Q. 백그라운드 상주 시 시스템 자원은 얼마나 소모되나요? ▾
Loadin은 Electron 같은 무거운 웹 브라우저 런타임을 포함하지 않고 순수 Go 1.23과 Win32 네이티브 서브시스템으로 컴파일되었습니다. 유휴 상태(Idle)에서는 CPU 점유율 0.0%, RAM 메모리는 15~20MB 수준으로 매우 가볍게 동작합니다.
Q. Windows SmartScreen 파란색 경고 창이 나타납니다. ▾
오픈소스 소프트웨어 특성상 고가의 상용 EV 코드 사이닝 인증서가 적용되지 않아 신규 빌드 파일 실행 시 Windows SmartScreen의 "알 수 없는 게시자" 경고가 나타날 수 있습니다. [추가 정보] → [실행]을 누르시면 정상적으로 실행되며, 본 웹사이트에 공개된 공식 SHA-256 해시값을 통해 파일의 순수 무결성을 직접 검증하실 수 있습니다.
Q. 브라우저 확장 프로그램이 꼭 필요한가요? ▾
필수는 아닙니다. Loadin 앱 내에서 직접 URL을 입력하거나, 클립보드에 다운로드 링크를 복사하면 자동으로 감지하여 추가할 수 있습니다. 다만 Chrome이나 Edge에서 웹 서핑 중 다운로드 버튼을 눌렀을 때 자동으로 Loadin 가속 창을 띄우려면 확장프로그램 설치를 권장합니다.
